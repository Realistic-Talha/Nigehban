This root layer defines the project's monorepo topology and operational surface rather than application logic. `pnpm-workspace.yaml` and `package.json` declare a pnpm workspaces layout under `apps/*` (frontends/APIs) and `packages/*` (shared libraries), with top-level scripts (`dev`, `build`, `lint`, `typecheck`, `clean`) delegated to Turborepo via `turbo.json`. The Turbo task graph enforces dependency ordering (`^build` before downstream tasks), marks `.next/**` and `dist/**` as build outputs, and disables caching for `dev`/`clean`. `docker-compose.yml` provisions two runtime dependencies — PostgreSQL with the pgvector extension (for vector similarity search in the scam/claim pipelines) and Redis (job queue / cache) — each with healthchecks and named volumes. `.env.example` documents the required secrets surface: database URL, Redis URL, Anthropic Claude API key, WhatsApp Business API tokens, a search API key, Cloudflare R2 object-storage credentials, and the public Next.js API base URL. `.gitignore` excludes Node artifacts, build outputs, env files, IDE state, Python caches (reflecting the Python-based AI pipeline described in the PRD), and Turbo's own cache directory. `docs/Nigehban_PRD.md` is the authoritative product specification describing the multi-agent verification pipeline (fact-check, scam-check, media-authenticity paths orchestrated by a Judge agent), data model, API surface, and hackathon phasing; it drives the expected shape of the `apps/` and `packages/` that live outside this scope.
